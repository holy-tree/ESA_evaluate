# 10 条预测区间测试样例

以下真实样例由本地 ESA 的 `labels.csv` 和 `anomaly_types.csv` 构造，用于验证上传、命中／误报、逐通道评分和图表导航，**不是算法性能结果**。文件名前缀为 `PIPELINE-CHECK`，避免与模型实验混淆。没有修改真实标签或默认评测范围。

## 文件与预期结果

选择对应 Mission、来源“真实 ESA”；评分固定为 **Anomaly + Rare Event + Communication Gap**：

| 文件 | 记录数 | 涉及通道数 | 命中预测区间 | 误报区间 | 参考宏平均 F0.5 |
|---|---:|---:|---:|---:|---:|
| `PIPELINE-CHECK-Mission1.csv` | 10 | 5 | 8 | 2 | 0.026129 |
| `PIPELINE-CHECK-Mission2.csv` | 10 | 8 | 8 | 2 | 0.027627 |
| `PIPELINE-CHECK-Mission3.csv` | 10 | 7 | 8 | 2 | 0.052414 |

每份文件中，**记录 1—8 命中标签，记录 9—10 为格式合法的误报**，序号不含表头。误报与该通道所有已知类别标签均不相交，仅按当前评测协议视作正常背景，不表示已人工逐点确认正常。

参考分使用 `manifest.json` 声明的版本、窗口和全部目标通道；Mission1 使用 `local-filtered-2007-v1`，Mission2／3 使用 `local-unversioned`，数据版本或范围变化后应重新验证。Mission3 将 Communication Gap 作为目标后，未预测的通信中断也计漏检，因此总体分数低于原两类协议。8 条命中不等于 8 个独立事件；同一 ID 可在多个通道出现，一次预测也可命中多个事件。

**Mission1／2 总分较低是预期结果：**这里只预测了完整历史中的少量事件，其余目标通道和历史事件仍参与宏平均，存在大量漏检。不能把“10 行中 8 行命中”当作总体召回率或 F0.5。

## 使用窗口

- Mission1：使用当前真实配置的默认评分窗口 `2007-01-01T00:00:00Z` → `2013-12-31T23:59:59.937000Z`；58 个目标通道，52 个通道具有可定义的 F0.5。
- Mission2：使用当前真实配置的完整默认窗口 `2000-01-01T00:00:16.284000Z` → `2003-06-30T23:59:52.416000Z`。
- **Mission3：必须使用以下自定义窗口并勾选确认：**

```text
开始：2000-01-01T00:00:00Z
结束：2004-01-01T00:00:00Z
```

Mission3 完整数据中存在反向标签，上述自检窗口与坏记录不相交；这是管线自检范围，不是官方测试集划分。

## 覆盖情况

- Mission1：按新标签重建，5 个通道，包含 Rare Event `id_117`／`id_26`、Anomaly `id_115`／`id_116`，以及 `id_189` 点事件。新标签没有 Communication Gap 区间，不构造虚假命中。
- Mission2：8 个通道，包含 Rare Event `id_34`、点事件 `id_548`，以及 Anomaly `id_630`、多通道事件 `id_636`。
- Mission3：7 个通道，包含多通道异常、`id_4` 的第二个不连续片段、Rare Event 和 `id_415` 点事件。其中记录 6 同时命中 Anomaly `id_4` 与 Rare Event `id_10`，因此总计检出 9 个事件—通道对，而不是 8 个。
- 三类事件同时参与评分；本样例没有命中的 Communication Gap 仍会计入对应通道漏检。

## 演示数据也已扩充

`demo_data/Mission1/predictions.csv`、`Mission2/predictions.csv`、`Mission3/predictions.csv` 各为 10 条，覆盖各自 2 个演示通道，同样为 8 条命中、2 条误报。演示数据仅有少量真实事件，因此包含同一事件的多次报警；逐通道事件检出数分别为 3、2、3，不能按命中行数重复计事件。

真实样例与演示样例时间和通道配置不同，不能混用。网页上传区会按当前来源提供对应下载，JSON 示例由 CSV 同步生成。

## 复核

```powershell
uv run python scripts/check_prediction_samples.py
```

该命令读取 YAML 配置的数据根目录，验证六份 CSV 的通道、时间、8/2 分布和预期事件 ID，并输出实际评分；直接调用评分核心，**不向排行榜写入自检记录**。
